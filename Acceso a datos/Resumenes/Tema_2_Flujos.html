1. Definición y tipos de ficheros

El flujo de datos o “Streams” son una secuencia ordenada de información que posee un recurso de entrada (flujo de entrada) y un recurso de salida (flujo de salida). Los Streams se basan en la unidireccionalidad, es decir, se usan sólo para leer o sólo para escribir, pero no ambas situaciones simultaneas.

  • Input = Entrada = Lectura (recibir datos).
  • Output = Salida = Escritura (enviar datos).
UsabilidadBytes (E/S)Caracteres (E/S)
FicherosFileInputStream, FileOutputStreamFileReader, FileWriter
ArraysByteArrayInputStream, ByteArrayOutputStreamCharArrayReader, CharArrayWriter
TuberíasPipedInputStream, PipedOutputStreamPipedReader, PipedWriter
BufferBufferedInputStream, BufferedOutputStreamBufferedReader, BufferedWriter
AnálisisPushbackInputStream, StreamTokenizerPushbackReader, LineNumberReader

2. Clases de flujos basados en tuberías

Las tuberías en Java, proporcionan la capacidad de comunicar dos hilos (threads) ejecutándose en la misma máquina virtual (JVM). Esto significa que las tuberías pueden ser tanto orígenes, como destinos de datos. En Java, las partes que se ejecutan deben pertenecer al mismo proceso y deben ser hilos diferentes.

Java
public class PipeDemo {

    public static void main(String[] args) throws IOException, InterruptedException {

        final PipedOutputStream salida = new PipedOutputStream();

        final PipedInputStream entrada = new PipedInputStream(salida); // connects both ends

        Thread escritor = new Thread(() -> {

            try (salida) {                                   // closes the pipe when done (Java 9+)
                salida.write("Hola por aquí!".getBytes(StandardCharsets.UTF_8));
            } catch (IOException e) {
                e.printStackTrace();
            }

        });

        Thread lector = new Thread(() -> {

            try (Reader r = new InputStreamReader(entrada, StandardCharsets.UTF_8)) {
                int c;

                while ((c = r.read()) != -1) {
                    System.out.print((char) c);
                }

                System.out.println();

            } catch (IOException e) {
                e.printStackTrace();
            }

        });

        escritor.start();

        lector.start();

        escritor.join();

        lector.join();
    }

}
  • Tubería (pipe): PipedOutputStream y PipedInputStream son los dos extremos de un canal en memoria. Lo que un hilo escribe en salida, otro lo lee de entrada. Sirven para comunicar hilos distintos.
  • Hilo escritor: escribe los bytes del texto y luego cierra salida (con try-with-resources). Ese cierre avisa al lector de que no habrá más datos.
  • Hilo lector: read() se bloquea hasta que hay datos y devuelve -1 solo cuando el escritor cerró y no queda nada por leer. Ahí termina el bucle.
  • join(): hace que main espere a que terminen ambos hilos.

3. Flujos basados en arrays

  • Acceso basado en bytes: ByteArrayInputStream, ByteArrayOutputStream.
  • Acceso basado en caracteres: CharArrayReader, CharArrayWriter.
Java
char[] chars = "hola amigo".toCharArray();

CharArrayReader charArrayReader = new CharArrayReader(chars);

int data = 0;

try {
    data = charArrayReader.read();

    while (data != -1) {
        // OPERACIONES
        System.out.println((char) data);
        data = charArrayReader.read();
    }

} catch (IOException e) {
    e.printStackTrace();
}

charArrayReader.close();

4. Clases de análisis para flujos de datos I

Las clases PushBackInputStream (byte a byte) y PushbackReader (caracteres) están diseñadas para el análisis de datos previo de un InputStream. En algunas ocasiones se necesita leer algunos bytes con anticipación para saber qué se aproxima, para así poder interpretar el byte actual.

Estos bytes leídos con anterioridad, serán de nuevo ‘empujados’ a la secuencia, para que posteriormente, los leamos cuando se haga de nuevo read().

Java
try {
    PushbackReader pushbackReader = new PushbackReader(
        new FileReader("C:\\temp\\pruebas\\pruebas2.txt")
    );

    int data = pushbackReader.read();
    System.out.println((char) data);

    pushbackReader.unread(data);

    data = pushbackReader.read();
    System.out.println((char) data);

    pushbackReader.close();

} catch (FileNotFoundException e) {
    e.printStackTrace();
} catch (IOException e) {
    e.printStackTrace();
}

5. Clases de análisis para flujos de datos II

Un token viene a estar relacionado con un “fragmento”, “una ficha”, “un trozo”. La clase StreamTokenizer tiene la capacidad de analizar el fichero por ‘trozos’ o ‘fragmentos’. Dichos fragmentos más tarde tendremos que evaluarlos y comprobar si son palabras o números. De hecho, StreamTokenizer es capaz de reconocer identificadores: números, comillas, espacios, etc

StreamTokenizer dispone de algunos métodos estáticos que nos dan información de la tipología de los distintos Tokens:

ConstanteDescripción
TT_EOFIndica el final del fichero (End Of File).
TT_EOLIndica el final de la línea (End Of Line).
TT_WORDIndica que el token es de tipo palabra, conjunto de letras.
TT_NUMBERIndica que el token evaluado es un número o una asociación de ellos.
Java
StreamTokenizer streamTokenizer = new StreamTokenizer(
    new StringReader("Hola mi edad es 45")
);

try {
    while (streamTokenizer.nextToken() != StreamTokenizer.TT_EOF) {

        if (streamTokenizer.ttype == StreamTokenizer.TT_WORD) {
            System.out.println(streamTokenizer.sval);

        } else if (streamTokenizer.ttype == StreamTokenizer.TT_NUMBER) {
            System.out.println(streamTokenizer.nval);

        } else if (streamTokenizer.ttype == StreamTokenizer.TT_EOL) {
            System.out.println();
        }
    }
} catch (IOException e) {
    e.printStackTrace();
}
  • El primero: si el token es de tipo palabra, mostraremos por pantalla dicha palabra.
  • El segundo condicional: si es de tipo número, mostraremos por pantalla el número.
  • El tercero: si es de tipo final de línea se imprimirá retorno de carro.

6. Clases de análisis para flujos de datos III

LineNumberReader es básicamente un objeto de tipo BufferedReader que almacena y cuenta el número de líneas leídas de caracteres. Está orientada a trabajar y analizar líneas completas.

Existen varios métodos clave para esta clase:

MétodoDescripción
getLineNumber()Devuelve el número de la línea que se está leyendo actualmente.
setLineNumber(int)Establece el número de la línea actual.
readLine()Devuelve una línea completa de texto (String).
read()Lee un carácter y devuelve su valor entero (int). Devuelve -1 si alcanza el final del flujo.
Java
public class EjemploLineNumber {

    public static void main(String[] args) {

        try (LineNumberReader lector = new LineNumberReader(new FileReader("pruebas.txt"))) {

            String linea;
            while ((linea = lector.readLine()) != null) {
                System.out.println(lector.getLineNumber() + ": " + linea);
            }

        } catch (IOException e) {
            e.printStackTrace();
        }
    }

}

7. Clases para el tratamiento de información

7.1. Introducción a las clases

  • DataOutputStream: escribe tipos primitivos (int, float, long...) en un fichero en formato binario. Se crea envolviendo un FileOutputStream.
  • DataInputStream: lee esos tipos primitivos. Se crea envolviendo un FileInputStream. Es subclase de InputStream, así que también hereda read() byte a byte y la lectura con array de bytes.
  • Ventaja sobre InputStream: InputStream solo procesa bytes sin tipo. Estas clases dan tipo a los datos.
  • Regla clave: se usa DataInputStream para leer ficheros escritos antes con DataOutputStream, y hay que leer en el mismo orden y con los mismos tipos con que se escribió. Con read() un -1 puede ser un dato o el fin de flujo, así que no se distinguen sin conocer la estructura.

7.2. Métodos

ClaseMétodoQué hace
DataOutputStreamwriteInt(int)Escribe un entero (4 bytes)
writeFloat(float)Escribe un float (4 bytes)
writeLong(long)Escribe un long (8 bytes)
close()Cierra el flujo y libera recursos
DataInputStreamread()Lee un byte (devuelve -1 al final)
readInt()Lee un entero
readFloat()Lee un float
readLong() / readDouble()Lee un long / un double
close()Cierra el flujo

Cada método solo acepta o devuelve su tipo. Además, los métodos readXxx() lanzan EOFException si se acaba el fichero antes de leer todos los bytes del tipo.

7.3. Ejemplo de código

Java
import java.io.*;

public class EjemploData {

    public static void main(String[] args) {

        // Escritura
        try (DataOutputStream out = new DataOutputStream(
                new FileOutputStream("data.bin"))) {

            out.writeInt(123);
            out.writeFloat(123.45F);
            out.writeLong(789);

        } catch (IOException e) {
            e.printStackTrace();
        }

        // Lectura: mismo orden y mismos tipos
        try (DataInputStream in = new DataInputStream(
                new FileInputStream("data.bin"))) {

            int entero = in.readInt();
            float numeroFloat = in.readFloat();
            long numeroLong = in.readLong();

            System.out.println("El entero es: " + entero);
            System.out.println("El float es: " + numeroFloat);
            System.out.println("El long es: " + numeroLong);

        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}

Salida:

Salida
El entero es: 123
El float es: 123.45
El long es: 789
